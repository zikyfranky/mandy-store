Interswitch (`GET` + `POST` — WebPay may POST back; support both by having POST delegate to GET or share a handler):
```typescript
import { NextRequest, NextResponse } from "next/server"
import { isPaymentMethodEnabled } from "@/lib/payments/config"
import { getOrderByGatewayReference } from "@/lib/orders/queries"
import { confirmOrderPaid } from "@/lib/payments/shared/confirm-order-paid"
import { interswitchAdapter } from "@/lib/payments/gateways/interswitch"

async function handle(req: NextRequest): Promise<NextResponse> {
  if (!isPaymentMethodEnabled("interswitch"))
    return NextResponse.redirect(new URL("/checkout?error=disabled", req.url))
  // ref: read from query (GET) or form body (POST) — hint ONLY, never trusted
  const ref = req.nextUrl.searchParams.get("txnref")
    ?? (req.method === "POST" ? String((await req.formData()).get("txnref") ?? "") : "")
  const order = await getOrderByGatewayReference(ref)
  if (!order) return NextResponse.redirect(new URL("/checkout?error=notfound", req.url))
  const v = await interswitchAdapter.verifyTransaction(ref)            // D-15 authoritative requery
  if (v.status !== "confirmed" || v.amountKobo < order.totalKobo)      // Pitfall 3 tamper guard
    return NextResponse.redirect(new URL(`/order/${order.guestToken}`, req.url))  // D-14 fallback
  const result = await confirmOrderPaid(order, { provider: "interswitch", eventId: "interswitch:" + ref })
  if (result.outcome === "oversold") await interswitchAdapter.refund(ref).catch(console.error)
  return NextResponse.redirect(new URL(`/order/${order.guestToken}`, req.url))
}
export const GET = handle
export const POST = handle
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → init action | Amount/method untrusted; toggle check first, total recomputed server-side (buildOrderContext) |
| gateway → callback route | Return params (resp, apprAmt) are attacker-controllable — used only as a lookup hint; status+amount come from server-side requery |
| gateway → webhook route | Notification body untrusted until the SHA-512 hash verifies; toggle-first before any work |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-71-12 | Spoofing | webhooks/gtpay + remita | mitigate | Raw body read before parse; SHA-512 notification hash verified; 400 on mismatch BEFORE confirmOrderPaid; toggle-first (Task 3) |
| T-71-13 | Tampering / Elevation | callback routes | mitigate | verifyTransaction server-side requery is sole authority; `status===confirmed && amountKobo>=totalKobo` guard; return params never trusted (D-15, Pitfall 3, Task 2 tampered-return test) |
| T-71-14 | Tampering | init actions | mitigate | Total always recomputed via buildOrderContext from getCart(); client amount ignored (CLAUDE.md, Task 1) |
| T-71-15 | — (idempotency) | callback + webhook | mitigate | Deterministic `<provider>:<ref>` eventId on BOTH paths → processed_webhook_events ON CONFLICT DO NOTHING; exactly one confirms (Pitfall 4, Task 2 collision test) |
| T-71-16 | Elevation of Privilege | all actions + routes | mitigate | isPaymentMethodEnabled is the FIRST statement in every action, callback, and webhook (D-18, PAY-12); disabled gateway rejected server-side |
| T-71-17 | Information Disclosure | init actions | mitigate | Adapters are server-only; secrets never returned; only the redirect URL + non-secret POST fields reach the client |
| T-71-18 | — (oversell) | callback + webhook | mitigate | Atomic `WHERE stock >= qty` inside the UNCHANGED confirmOrderPaid + adapter.refund on oversold (D-09) |
</threat_model>
