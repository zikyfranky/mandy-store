## What was built
- **`webpay-core.ts`** — one config-driven module: `buildWebPayRedirect` (→ D-16 POST-redirect union) + `verifyWebPay` (server-side requery → VerifyResult) + `sha512` helper + `NGN_NUMERIC` ("566"). The core reads NO env and branches on NO provider — all divergence lives in the `WebPayConfig` passed in (D-12).
- **`interswitch.ts`** — `interswitchConfig` + `interswitchAdapter`. Request hash `SHA-512(txnRef+productId+payItemId+amountKobo+redirectUrl+macKey)`; requery hash `SHA-512(productId+txnRef+macKey)` (different order, Pitfall 2). Kobo passthrough. MAC key `.trim()`ed. Sandbox endpoints default; `parseRequery` maps `ResponseCode`/`Amount`.
- **`gtpay.ts`** — `gtpayConfig` + `gtpayAdapter`, second config over the same core. GTBank host, `gtpay_*` field names (current `gtpay_hash`, not deprecated `gtpay_tranx_hash`), hash `SHA-512(mertId+tranxId+amt+curr+custId+notiUrl+hashKey)`. Kobo passthrough, hash key trimmed.
- Both `refund()` degrade to log + manual (A5 — refund API unconfirmed at sandbox).
