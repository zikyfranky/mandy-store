**Current provider union** (`types.ts:9`):

```
**Extend to** (D-18):

```

**Current `initPayment` signature** (`types.ts:46-53`) returns `Promise<Record<string, unknown>>`. D-16 evolves this into a tagged union. Add an `InitResult` type and change the interface return:

  | { mode: "popup"; [k: string]: unknown }             // Paystack/Flutterwave (existing fields)

### `src/lib/payments/gateways/interswitch.ts` (NEW — service/adapter)

**Analog:** `src/lib/payments/gateways/paystack.ts` (structure) + `flutterwave.ts` (unit-guard idea). Uses `webpay-core.ts` for hash + requery mechanics.

**Imports + server-only header** (copy from `paystack.ts:1,16`):
```typescript
import "server-only"
import crypto from "crypto"
import type { GatewayAdapter, VerifyResult, NormalizedStatus } from "./types"
```

**Adapter export shape** (mirror `paystack.ts:147-173`) — `provider`, `initPayment`, `verifyTransaction`, `refund`. Key differences from Paystack:
- `initPayment` returns `{ mode: "redirect", url, method: "POST", fields }` (RESEARCH Pattern 2), NOT a popup object.
- `verifyTransaction` is a server-side **requery** (RESEARCH Pattern 3), NOT trust of return params.
- Amount unit: **kobo** — pass `amountKobo` unchanged (same as Paystack; RESEARCH Pitfall 1).

**Request hash** (RESEARCH Pattern 2 — plain SHA-512, NOT HMAC; concat order is load-bearing):
```typescript
// hashInput = txn_ref + product_id + pay_item_id + amount + site_redirect_url + macKey
const hash = crypto.createHash("sha512").update(hashInput).digest("hex")
```
**Requery hash** (different concat order — RESEARCH Pitfall 2):
```typescript
// requeryHash = product_id + txn_ref + macKey   (sent as `Hash:` header)
```
**Endpoints:** POST `https://sandbox.interswitchng.com/collections/w/pay` (test); requery GET `.../collections/api/v1/gettransaction.json`. `ResponseCode "00"` → `"confirmed"` (Pitfall 7). Amount returned in kobo — passthrough.

**verifyTransaction return** mirrors `paystack.ts:101-106` VerifyResult shape (status, amountKobo, currency, reference).

### `src/app/api/payments/<gw>/callback/route.ts` (NEW — route, verify-on-return)

**Analog:** `verifyPaystackPayment` (`actions/paystack.ts:135-199`) for the verify/confirm/oversold logic + the status-route file shape (`api/order/status/[token]/route.ts`) for the Route Handler signature. RESEARCH Code Examples has the exact skeleton.

**Structure** (per-gateway routes recommended — RESEARCH open Q2):
```typescript
// Do NOT export `runtime` (Pitfall — breaks cacheComponents:true; see stripe/route.ts:13-15 note)
export async function GET(req: NextRequest): Promise<NextResponse> {
  if (!isPaymentMethodEnabled("interswitch"))                        // toggle FIRST (D-18)
    return NextResponse.redirect(new URL("/checkout?error=disabled", req.url))
  const ref = req.nextUrl.searchParams.get("txnref") ?? ""           // hint ONLY — never trust
  const order = await getOrderByGatewayReference(ref)
  if (!order) return NextResponse.redirect(new URL("/checkout?error=notfound", req.url))
  const v = await interswitchAdapter.verifyTransaction(ref)          // D-15 authoritative requery
  if (v.status !== "confirmed" || v.amountKobo < order.totalKobo)    // amount guard (paystack.ts:170)
    return NextResponse.redirect(new URL(`/order/${order.guestToken}`, req.url))  // D-14 fallback → interstitial
  const result = await confirmOrderPaid(order, {
    provider: "interswitch",
    eventId: "interswitch:" + ref,                                    // same key a webhook uses (Pitfall 4)
  })
  if (result.outcome === "oversold")
    await interswitchAdapter.refund(ref).catch(console.error)
  return NextResponse.redirect(new URL(`/order/${order.guestToken}`, req.url))
}
```
**Deltas per gateway:** the return-param name (`txnref` / `gtpay_tranx_id` / RRR), the `eventId` prefix (`"interswitch:"` / `"gtpay:"` / `"remita:"` — Pitfall 4), and whether a POST body must also be read (some gateways POST back; support both GET and POST). Redirect-to-`/order/[guestToken]` reuses the existing order page + `PaymentProcessingView` (UI-SPEC §4e; REUSE unchanged). Cancelled/error → `/checkout?error=cancelled|disabled|notfound`.

## Shared Patterns

### Toggle enforcement (D-18 / D-06 / PAY-12)
**Source:** `src/lib/payments/config.ts:14-34`
**Apply to:** the `config.ts` switch (add 3 cases + list entries), and as the FIRST statement in every new action, callback route, and webhook route.
```typescript
case "interswitch":
  return process.env.ENABLE_INTERSWITCH === "true"
    && !!process.env.INTERSWITCH_MAC_KEY && !!process.env.INTERSWITCH_MERCHANT_CODE
case "gtpay":
  return process.env.ENABLE_GTPAY === "true"
    && !!process.env.GTPAY_HASH_KEY && !!process.env.GTPAY_MERCHANT_ID
case "remita":
  return process.env.ENABLE_REMITA === "true"
    && !!process.env.REMITA_API_KEY && !!process.env.REMITA_MERCHANT_ID
// and append all 3 to the enabledPaymentMethods() tuple (config.ts:33)
```
Also widen the `PaymentMethod` union (`config.ts:7`). Toggle-first is verbatim from `paystack.ts:43` / `paystack/route.ts:26`.

### Order creation + total recompute (never trust client price — CLAUDE.md)
**Source:** `buildOrderContext()` in `src/lib/actions/checkout.ts:89-141`
**Apply to:** all 3 new init actions — call verbatim; use `ctx.totals.totalKobo` (server-computed kobo) as the gateway amount. Never accept a client amount.

### Idempotent confirmation (D-04 / D-15 — the untouchable core)
**Source:** `confirmOrderPaid()` in `src/lib/payments/shared/confirm-order-paid.ts:66-159`
**Apply to:** every callback route AND every optional webhook route. Call unchanged. It performs the idempotency insert (`:76-86`), atomic `WHERE stock >= qty` decrement (`:100-116`), oversold detection (`:125-139`), and email. **Do NOT modify this file** (RESEARCH: changing it is a red flag). Deterministic `eventId = "<provider>:<ref>"` on BOTH the callback and the webhook (Pitfall 4) so exactly one wins.

### Order lookup by gateway reference
**Source:** `getOrderByGatewayReference()` in `src/lib/orders/queries.ts:58-64`
**Apply to:** every callback + webhook route. Reused verbatim — keyed on the existing `gatewayReference` column (no new query, no schema change; RESEARCH Runtime State Inventory). Remita stores its RRR here.

### SHA-512 hashing (plain, NOT HMAC)
**Source:** `crypto` usage in `src/app/api/webhooks/paystack/route.ts:38-41` (that is HMAC — the webhook signature case). For these gateways use **plain** SHA-512 of a field concat:
```typescript
import crypto from "crypto"
const hash = crypto.createHash("sha512").update(concatString).digest("hex")
```
**Apply to:** `webpay-core.ts`, `interswitch.ts`, `gtpay.ts`, `remita.ts`, and the GTPay/Remita webhook hash verify. Concat order is load-bearing and DIFFERS per gateway and per operation (request vs requery) — encode with a source-citing comment and unit-test against a fixture (Pitfall 2). Trim env values (128-char MAC key picks up stray whitespace).

### Amount unit per gateway (the 100× bug — Pitfall 1)
**Source:** `flutterwave.ts:41-47` (naira conversion + `> ₦1M` guard) vs `paystack.ts:42,103` (kobo passthrough)
**Apply to:** Interswitch/GTPay → kobo passthrough (like Paystack). Remita → ÷100 on init, ×100 on verify (like Flutterwave), with the `> ₦1M` sanity guard. Normalize `VerifyResult.amountKobo` to kobo for ALL three so the callback amount guard (`v.amountKobo < order.totalKobo`) is uniform.

### Status normalization (Pitfall 7)
**Source:** `paystack.ts:91-99` / `flutterwave.ts:100-108`
**Apply to:** each adapter's `verifyTransaction` maps its native success code → `NormalizedStatus`: Interswitch `ResponseCode "00"`, GTPay `gtpay_tranx_status_code "00"`, Remita `status "00"/"01"` → `"confirmed"`; else `"failed"`/`"pending"`. Unit-test the mapping.

### Route Handler conventions (Next.js 16)
