```typescript
  provider: "interswitch" | "gtpay"
  payUrl: string          // POST target (hosted page)
  requeryUrl: string      // GET requery endpoint
  fieldNames: {           // gateway-specific POST field names
    merchant: string; txnRef: string; amount: string; currency: string;

  buildRequeryHash(txnRef: string): string

}
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| adapter → gateway (init) | Amount comes from server-computed totalKobo (never client); passed as kobo |
| gateway → adapter (requery) | Return/requery status+amount treated as authoritative ONLY when fetched server-side; concat-order hash guards integrity |
| env → adapter | MAC key / hash key are server-only (import "server-only"); trimmed to avoid whitespace hash failures |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-71-04 | Tampering | request/requery SHA-512 hash | mitigate | Exact documented concat order encoded + unit-tested against a fixture (Pitfall 2); request vs requery orders differ and are separately tested |
| T-71-05 | Information Disclosure | interswitch.ts / gtpay.ts | mitigate | `import "server-only"` on both; MAC/hash keys read from server env, never returned to client; only the redirect URL + non-secret POST fields reach the client |
| T-71-06 | Tampering | amount unit (Pitfall 1) | mitigate | kobo passthrough for both (matches Paystack); requery amount normalized to kobo for the uniform downstream `amountKobo >= totalKobo` guard (plan 04) |
| T-71-07 | Spoofing | gtpay notify hash | transfer | GTPay notify-hash verification is implemented in the plan-04 webhook route; here the adapter only builds request/requery hashes |
</threat_model>
