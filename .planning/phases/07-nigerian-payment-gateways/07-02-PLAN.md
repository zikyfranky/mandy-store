Adapter contract (src/lib/payments/gateways/types.ts):
```typescript
export interface GatewayAdapter {
  readonly provider: "paystack" | "flutterwave"
  initPayment(params: { email; amountKobo; reference; orderId; customerName; phone? }): Promise<Record<string, unknown>>
  verifyTransaction(reference: string): Promise<VerifyResult>  // VerifyResult.amountKobo normalized to kobo
  refund(reference: string, amountKobo?: number): Promise<void>
}
export interface VerifyResult { status: "confirmed"|"failed"|"pending"; amountKobo: number; currency: string; reference: string }
```

Shared confirm path (src/lib/payments/shared/confirm-order-paid.ts):
```typescript
export type ConfirmResult = { outcome: "confirmed" } | { outcome: "duplicate" } | { outcome: "oversold"; refundNeeded: true }
export async function confirmOrderPaid(order: OrderWithItems, { provider, eventId }: { provider: string; eventId: string }): Promise<ConfirmResult>
```

Toggle (src/lib/payments/config.ts): `isPaymentMethodEnabled("paystack")`.

Paystack API (RESEARCH Patterns 1, 4; Code Examples):
- Initialize: POST https://api.paystack.co/transaction/initialize, Bearer PAYSTACK_SECRET_KEY, body { email, amount (KOBO), reference, currency:"NGN", metadata:{orderId} } → data.access_code, data.reference.
- Verify: GET https://api.paystack.co/transaction/verify/:reference, Bearer secret → data.status ("success"), data.amount (KOBO), data.currency.
- Refund: POST https://api.paystack.co/refund, body { transaction: reference } (omit amount for full refund).
- Webhook: header `x-paystack-signature`; HMAC SHA-512 of RAW body with PAYSTACK_SECRET_KEY (hex). Event `charge.success`; data.reference; data.amount (KOBO). No top-level event id → eventId = "paystack:"+data.reference.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| customer browser → initPaystackPayment | Client-submitted amount/email; amount recomputed server-side, toggle-gated |
| Paystack webhook → /api/webhooks/paystack | Untrusted POST; HMAC SHA-512 signature verified before any processing |
| popup callback → verifyPaystackPayment | Client provides only reference; server re-fetches authoritative status/amount from Paystack |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-05 | Spoofing | Paystack webhook | mitigate | HMAC SHA-512 of raw body with PAYSTACK_SECRET_KEY; mismatch → 400 (Task 3) |
| T-07-06 | Tampering | verifyPaystackPayment | mitigate | Server re-fetches from Paystack verify; reject when verified amountKobo < order.totalKobo (Task 2) |
| T-07-07 | Repudiation | confirm path | mitigate | eventId "paystack:"+reference shared by webhook + callback → idempotent (Task 2/3) |
| T-07-08 | Elevation | stock decrement | mitigate | Atomic conditional decrement in confirmOrderPaid; oversold → paystackRefund + payment_failed (Task 2/3) |
| T-07-09 | Access Control | init/verify actions + webhook | mitigate | isPaymentMethodEnabled("paystack") first statement in every action/route (PAY-12, Task 2/3) |
| T-07-10 | Info Disclosure | initPaystackPayment return value | mitigate | Only NEXT_PUBLIC_PAYSTACK_PUBLIC_KEY returned to client; secret never leaves server (Task 2) |
</threat_model>
