# Phase 6 — UI Design Contract: Customer Accounts

> Visual and interaction contract for `/account`, `/account/orders`, `/account/orders/[id]`.
> Generated by gsd-ui-researcher (--auto mode, no questions asked — upstream CONTEXT.md D-01..D-08
> and the existing indigo design system fully determine this contract). Verified by gsd-ui-checker.
>
> **Scope note:** This is a small, reuse-heavy phase. No new design language is introduced. The
> only net-new visual component is `OrderHistoryCard`. Every other surface composes components
> that already exist and ship unchanged.

## Surfaces

### Surface 1 — `/account` (landing)

**Route:** `src/app/account/page.tsx` (new). Dual-auth: `proxy.ts` redirect (layer 1) +
`verifySession()` inside the Suspense-wrapped content (layer 2), mirroring the existing
`/account/orders` stub exactly.

**Layout** (mirrors `/order/[token]`'s container sizing, scaled down since content is minimal):

```
<main class="max-w-2xl mx-auto px-4 sm:px-6 py-12">
  <div class="rounded-2xl bg-surface border border-border p-8 space-y-6">
    <h1 class="text-2xl font-semibold text-foreground">Your account</h1>
    <p class="text-sm text-muted">Signed in as {email}</p>

    <!-- Primary CTA -->
    <Link href="/account/orders"
      class="inline-flex items-center rounded-xl bg-brand hover:bg-brand-strong text-white
             px-5 py-2.5 text-sm font-semibold transition-colors
             focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-brand
             focus-visible:ring-offset-2">
      View order history
    </Link>

    <hr class="border-t border-border" />

    <!-- Sign out — neutral, non-destructive -->
    <form action={logout}>
      <button type="submit"
        class="rounded-lg border border-border px-4 py-2 text-sm font-semibold text-foreground
               hover:bg-brand-soft/50 transition-colors focus-visible:outline-none
               focus-visible:ring-2 focus-visible:ring-brand focus-visible:ring-offset-2">
        Sign out
      </button>
    </form>
  </div>
</main>
```

**States:**
- **Loading:** `Suspense` fallback = pulsing placeholder block, same shape/technique as the

- **Error:** none rendered — `verifySession()` failure redirects via `proxy.ts`/DAL before content
  renders; no client-visible error state needed here.
- **Empty:** not applicable (landing always has an email once authenticated).

### Surface 2 — `/account/orders` (order history list)

**Route:** `src/app/account/orders/page.tsx` (grow the existing stub — keep its `verifySession()`
-first-inside-Suspense structure unchanged, D-08).

**Layout:**

```
<main class="max-w-4xl mx-auto px-4 py-10">
  <h1 class="text-2xl font-semibold text-foreground mb-6">Order history</h1>

  <!-- populated state -->
  <div class="space-y-4">
    {orders.map(order => <OrderHistoryCard key={order.id} order={order} />)}
  </div>
</main>
```

**`OrderHistoryCard` (NEW, `src/components/order/OrderHistoryCard.tsx`) — spec:**

Whole card is a single `<Link href={"/account/orders/" + order.id}>` (the entire card is
clickable, not just the reference text — this matches the touch-target-friendly pattern already
used for admin table rows' hover state, upgraded to a full-card tap target for mobile).

```
<Link href={`/account/orders/${order.id}`}
  class="block rounded-2xl bg-surface border border-border p-5 hover:border-brand/40
         transition-colors focus-visible:outline-none focus-visible:ring-2
         focus-visible:ring-brand focus-visible:ring-offset-2">
  <div class="flex flex-wrap items-center justify-between gap-3">
    <div>
      <p class="font-mono text-sm font-semibold text-foreground">{order.reference}</p>
      <p class="text-sm text-muted mt-0.5">
        {order.createdAt.toLocaleDateString("en-NG", { day: "numeric", month: "short", year: "numeric" })}
      </p>
    </div>
    <OrderStatusBadge status={order.status} />
    <div class="text-right">
      <p class="text-sm text-muted">{order.itemCount} item{order.itemCount === 1 ? "" : "s"}</p>
      <p class="text-sm font-semibold text-foreground">{formatNGN(order.totalKobo)}</p>
    </div>
  </div>
</Link>
```

Date format decision: **absolute date** (`9 Jul 2026`), not the admin list's relative-time
(`relativeDate()`). Customers scan their own small order history and want the actual date, not
"3 weeks ago" — admin triage is the only surface that benefits from relative time. Do not port
`relativeDate()` here.

**States:**
- **Empty** (D-02): inline in the page (no extracted component — mirrors `CartEmptyState`'s visual
  language exactly, same icon size/color):
  ```
  <div class="flex flex-col items-center justify-center py-16 text-center rounded-2xl
              bg-surface border border-border">
    <!-- Heroicons InboxIcon or ShoppingBagIcon, 48px, text-zinc-300 dark:text-zinc-600 -->
    <h2 class="text-2xl font-semibold text-foreground mt-4">No orders yet</h2>
    <p class="text-sm text-muted mt-2 max-w-sm">
      When you place an order, it will show up here.
    </p>
    <Link href="/" class="mt-6 inline-flex items-center rounded-xl bg-brand hover:bg-brand-strong
      text-white px-6 py-3 text-sm font-semibold transition-colors focus-visible:outline-none
      focus-visible:ring-2 focus-visible:ring-brand focus-visible:ring-offset-2">
      Browse products
    </Link>
  </div>
  ```
- **Loading:** `Suspense` fallback = 3 pulsing card-shaped placeholders (`h-20 rounded-2xl
  bg-zinc-100 dark:bg-zinc-800/50 animate-pulse` × 3 in a `space-y-4`), same technique as the
  admin `OrdersSkeleton`.
- **Error:** route-level `error.tsx` (or an inline try/catch fallback if the planner prefers) using
  the same visual language as the `/order/[token]` `OrderNotFound` card: `rounded-2xl bg-surface
  border border-border p-8 text-center space-y-4`, heading "Something went wrong loading your
  orders", body "Please try refreshing the page. If this keeps happening, contact support.", no
  destructive styling (this is a neutral/informational error, not the customer's fault).

### Surface 3 — `/account/orders/[id]` (order detail, IDOR-safe)

**Route:** `src/app/account/orders/[id]/page.tsx` (new). Loads via
`getOrderForUser(session.user.id, id)` (D-04/D-05) — **404, never 403**, on any mismatch or
missing order.

**Layout** (deliberately mirrors `/order/[token]`'s confirmed-state card almost exactly — same
container, same card, same two reused blocks, so a customer recognizes it as "the same order
page" they saw right after checkout):

```
<main class="max-w-2xl mx-auto px-4 sm:px-6 py-12">
  <div class="rounded-2xl bg-surface border border-border p-8 space-y-6">
    <div>
      <OrderStatusBadge status={order.status} />
      <h1 class="text-2xl font-semibold text-foreground mt-3">Order {order.reference}</h1>
      <p class="text-sm text-muted mt-1">
        Placed {order.createdAt.toLocaleDateString("en-NG", { day: "numeric", month: "short", year: "numeric" })}
      </p>
    </div>

    <hr class="border-t border-border" />

    <OrderSummaryLines
      items={order.items}
      subtotalKobo={order.subtotalKobo}
      shippingKobo={order.shippingKobo}
      totalKobo={order.totalKobo}
    />

    <ShippingAddressBlock
      shippingName={order.shippingName}
      shippingPhone={order.shippingPhone}
      shippingStreet={order.shippingStreet}
      shippingCity={order.shippingCity}
      shippingState={order.shippingState}
      shippingLandmark={order.shippingLandmark ?? null}
    />

    <!-- Payment method — small block, ported pattern (icon + label), not a new visual language -->
    <div>
      <h2 class="text-sm font-semibold text-foreground mb-2">Payment method</h2>
      <span class="inline-flex items-center gap-1.5 text-sm text-muted">
        {/* CreditCardIcon or BuildingLibraryIcon, 16px, text-muted */}
        {paymentMethodLabel}
      </span>
    </div>

    <hr class="border-t border-border" />

    <Link href="/account/orders"
      class="text-sm font-semibold text-brand hover:text-brand-strong
             focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-brand
             focus-visible:ring-offset-2 rounded">
      ← Back to order history
    </Link>
  </div>
</main>
```

Total is shown **only** as captured at purchase (`order.totalKobo` from the snapshot,
via `OrderSummaryLines` — never recomputed, per SC2/D-03).

**States:**
- **404 (IDOR-safe, D-04):** styled card, reusing the exact structure/classes of `/order/[token]`'s
  `OrderNotFound` (`DocumentMagnifyingGlassIcon`, 48px, `text-zinc-300 dark:text-zinc-600`):
  ```
  <main class="max-w-2xl mx-auto px-4 sm:px-6 py-12">
    <div class="rounded-2xl bg-surface border border-border p-8 text-center space-y-4">
      <!-- DocumentMagnifyingGlassIcon, 48px -->
      <h1 class="text-2xl font-semibold text-foreground">Order not found</h1>
      <p class="text-sm text-muted">
        This order doesn't exist or isn't linked to your account. Check your order history
        for the correct link.
      </p>
      <Link href="/account/orders" class="text-sm font-semibold text-brand hover:text-brand-strong">
        Back to order history
      </Link>
    </div>
  </main>
  ```
  **Do not** call Next's `notFound()` (would render the generic Next 404, breaking the storefront
  shell) — return this styled card directly from the page component, exactly like
  `/order/[token]/page.tsx` does for its own `OrderNotFound`. Render this same card whether the
  order genuinely doesn't exist OR exists but belongs to another user — **identical response in
  both cases**, so no information about the order's existence leaks (D-04 core security
  requirement).
- **Loading:** `Suspense` fallback mirrors `/order/[token]`'s `OrderPageSkeleton` structure exactly
  (`h-12 w-12 rounded-full`, `h-8 w-48 rounded`, `h-4 w-64 rounded`, `h-32 rounded-xl`, all
  `bg-zinc-200 dark:bg-zinc-700 animate-pulse`).
- **Error:** same generic error-card language as Surface 2 (unexpected DB/query failure, not a
  404) — "Something went wrong loading this order" / retry copy.

## Accessibility

- Every interactive element (`OrderHistoryCard` link, buttons, back-links) carries
  `focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-brand
  focus-visible:ring-offset-2` — matches the sitewide focus-ring convention, never removed without
  replacement.
- `OrderStatusBadge` already pairs icon + text label (never color-only) — reused as-is, so status
  meaning survives for color-blind users and screen readers alike.
- The whole-card `<Link>` on `OrderHistoryCard` gives a single large (`p-5`, effectively >44px tall)
  tap target — no separate small "view" link needed, and no nested interactive elements inside the
  card (avoids link-in-link a11y issues).
- Card date `toLocaleDateString` output is plain visible text (no `title`-only relative time that
  would hide the real date from screen readers, unlike the admin list's `relativeDate()` pattern —
  another reason this list intentionally does not reuse that admin pattern).
- 404 and error states use `<h1>`/`<h2>` heading hierarchy consistent with the rest of the app;
  icons are `aria-hidden="true"` (matches every existing inline SVG icon in this codebase).
- Sign-out is a `<form action={logout}>` + `<button type="submit">`, not a bare link, so it's
  reachable and activatable via keyboard/screen reader exactly like the existing `AdminSidebar`
  sign-out control.

## Decision Log (auto-selected, --auto mode, no questions asked)

1. **Shell = storefront `SiteHeader`, not `AdminSidebar`.** CONTEXT D-07 explicitly says "reuse the
   existing site header/auth patterns" — accounts are customer-facing and off the critical path;
   the admin shell would be the wrong visual register entirely.
2. **`OrderHistoryCard` is the only net-new component.** Everything else (empty state, 404,
   skeletons) is page-local inline JSX mirroring an existing local pattern 1:1
   (`CartEmptyState`/admin empty state → history empty state; `/order/[token]`'s `OrderNotFound`/
   `OrderPageSkeleton` → detail 404/skeleton), per the phase brief's "minimal net-new components"
   instruction.
3. **Absolute date on the list card, not relative time.** The admin orders table uses
   `relativeDate()` for fast triage of many orders; a customer's own (typically short) order
   history reads better with the literal date. Deliberately diverges from the admin pattern for UX
   reasons, not oversight.
4. **Whole-card `<Link>`, not a text-only "view" link.** Larger tap target, simpler DOM, avoids
   nested-interactive a11y pitfalls, and matches the "list of order cards... each card links to its
   detail page" wording in D-01 literally.
5. **Empty-state CTA href is `/` per D-02's literal wording** ("browse products (`/`)"), copy
   "Browse products" — chosen over mimicking `CartEmptyState`'s `/products` + "Start shopping" so
   the decision record matches D-02 exactly; functionally near-identical either way since `/` and
   `/products` both lead to browsing.
6. **404, not 403, and identical response for "doesn't exist" vs. "not yours."** Directly
   implements D-04's core IDOR requirement — this is a security decision expressed as a UI
   decision (one styled card, one code path, no branching on "which kind of not-found").
7. **Payment-method display is a ported pattern, not a cross-module import**, because the existing
   implementation (`paymentMethodDisplay()`) lives in an admin-scoped page file
   (`src/app/admin/orders/page.tsx`) that customer code should not import from. Flagged for the
   planner to either duplicate the ~10-line helper or lift it to a shared `src/lib/orders/format.ts`
   — either is fine, no new visual language either way.
8. **No new spacing/typography/color tokens.** Every value in this contract is copy-pasted from an
   existing component already in the codebase (see Component Inventory) — this phase's smallness
   is a feature, not an oversight.
