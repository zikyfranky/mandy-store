<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client login POST -> Credentials.authorize | untrusted identifier/password crosses here |
| server module -> client bundle | DAL + email sender must never reach the browser |
| app -> Resend API | outbound email with verification token |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-04 | Spoofing | account creation / login | mitigate | emailVerified must be non-null before login — `authorize()` returns null otherwise (D-02, RESEARCH Pitfall 5) |
| T-01-05 | Information Disclosure | password storage | mitigate | argon2id verify only; plaintext never stored/compared; passwordHash column never returned to client (ASVS V2) |
| T-01-06 | Tampering | session token | mitigate | Auth.js DB session strategy; `sessionToken` is `crypto.randomUUID()` high-entropy; httpOnly/secure/sameSite cookie managed by Auth.js (ASVS V3) |
| T-01-07 | Elevation of Privilege | stale/banned session | mitigate | DB-backed sessions (D-06) enable server-side revocation; deleting the session row logs the user out everywhere |
| T-01-08 | Information Disclosure | DAL / email sender in client bundle | mitigate | `import "server-only"` at top of `dal.ts` and `send-verification.ts` causes a build error if imported client-side |
| T-01-09 | Elevation of Privilege | admin role read | mitigate | role read only from verified session in DAL; never from URL/form (RESEARCH Pitfall 7) |
</threat_model>
