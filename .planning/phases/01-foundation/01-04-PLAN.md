|----------|-------------|
| browser navigation -> proxy.ts | first gate on protected route requests |
| browser -> protected Server Component / Server Action | proxy does NOT cover Server Actions; re-verify required |
| verification link (token in URL) -> verify-email page | bearer token in query string |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-16 | Elevation of Privilege | Server Action / protected page bypass | mitigate | proxy is UX only; admin/page.tsx calls `verifyAdminSession()` and account/orders calls `verifySession()` in-page (CLAUDE.md double-auth, RESEARCH Pitfall 3) |
| T-01-17 | Elevation of Privilege | non-admin reaching /admin | mitigate | proxy redirects `role !== "admin"` to / AND verifyAdminSession re-checks server-side (D-09) |

| T-01-19 | Information Disclosure | verification token in URL/logs | accept | standard email-verification pattern; token is single-use + 24h expiry (mitigated in Plan 03); not logged by app |
</threat_model>
