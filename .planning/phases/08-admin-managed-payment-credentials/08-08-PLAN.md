## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-23 | Spoofing | Stripe webhook signature verification | mitigate | Fail-closed guard rejects (400) before calling `constructEvent` at all if the resolved `webhook_secret` is empty — avoids relying on the Stripe SDK's own internal behavior for an undefined secret, which is less predictable/testable than an explicit guard |
| T-08-24 | Information Disclosure | `stripeClient` reuse across the resolved key and signature verification | accept | The Stripe client instance (keyed by `secret_key`) and the webhook secret (`webhook_secret`) are two independent fields resolved separately — using the SAME provider config object for both in one request is fine since both fields belong to the same trust boundary (server-only, same gateway) |
</threat_model>
