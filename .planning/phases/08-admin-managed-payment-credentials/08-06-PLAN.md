<objective>
Migrate the Paystack and Flutterwave webhook routes' signing-secret resolution onto the
resolver (D-03a), with an explicit fail-closed guard: if the resolved secret is empty (no DB
row, no env var), reject with 400 BEFORE attempting any HMAC compare — never compute a hash
against `undefined`/empty and never fall through to an accidental match.

Purpose: the webhook signature check is the single highest-stakes credential read in the
entire phase — an attacker who can make this fail open (accept a forged webhook) can create
fraudulent `payment_confirmed` orders. Getting the "resolve, then guard empty, then verify"
order right here — and testing it explicitly — is what ADMN-07's "fails closed" success
criterion actually means in practice.
Output: both webhook routes resolver-backed with an explicit empty-secret 400 guard; both
existing test files extended with a "fail-closed" case and a DB-mock added.
</objective>
