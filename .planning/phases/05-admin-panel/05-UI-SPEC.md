# Phase 5 — UI Design Contract: Admin Panel

> Visual and interaction contract for the owner-facing `/admin` surfaces (Products, Orders,
> Settings). Generated by gsd-ui-researcher in `--auto` mode (no user prompts — all values are
> sensible defaults derived from the existing indigo design system already live in the codebase).
> Verified by gsd-ui-checker.

**Auto-mode note:** No questions were asked. Every value below either (a) was already locked by
`05-CONTEXT.md`, (b) is a direct read of an existing token/component in the codebase, or (c) is a
default chosen for internal consistency with (a)/(b). See the Decision Log at the end for the full
rationale trail.

| Property | Value |

Continue inlining SVGs in the same style — do not introduce a new icon package. |

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps (`gap-1`), micro adjustments |
| sm | 8px | Compact stacks (`gap-2`, `space-y-2`), input vertical rhythm |
| md | 16px | Default element spacing (`gap-4`, `p-4`, card internal padding on compact surfaces) |
| lg | 24px | Section padding (`p-6` — matches `CheckoutForm` section cards), stacked section gaps (`space-y-6`) |
| xl | 32px | Layout gaps between major admin-shell regions (`gap-8`) |
| 2xl | 48px | Major section breaks (rare in admin; reserved for empty-state vertical padding `py-12`) |
| 3xl | 64px | Page-level top/bottom padding on wide empty states (`py-16`, matches `EmptyState.tsx`) |

Exceptions (already established in the codebase — reuse, do not invent new ones):
- **2px** (`mt-0.5`) — icon optical alignment next to single-line text (used in `OOSWarningBanner`).
- **10px** (`px-2.5`, `py-2.5`) — the default input/select padding unit set by `CheckoutForm`'s
  `inputClass` helper. All admin text inputs, selects, and textareas reuse this exact class.
- **12px** (`gap-3`, `p-3`) — card-internal icon+text row gaps (matches `PaymentMethodSelector`
  radio rows, `CartLineItem` gaps).
- **20px** (`px-5`) — list-row horizontal padding where a denser edge-to-edge table look is
  wanted (matches `CartLineItem` drawer rows); use for Products/Orders table cell padding.
- **44px** (`min-h-11 min-w-11`) — minimum interactive touch target for icon-only buttons (trash,
  close, sign-out on mobile), matching `CartLineItem`'s remove button and `SiteHeader`'s account
  icon. Applies even though admin is desktop-first (SC/D-01 requires "doesn't break on mobile").

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | 400 (regular) | 1.5 — secondary/help text, table cell values, descriptions (e.g. `text-sm text-muted`) |
| Label | 14px (`text-sm`) | 600 (semibold) | 1.25 — form labels, table column headers, button text, badge text, primary values (`text-sm font-semibold text-foreground`) |
| Heading | 24px (`text-2xl`) | 600 (semibold) | 1.2 — page titles ("Products", "Orders", "Settings") and section-card headings ("Add product", "Order MS-XXXXXX"), matching the existing `src/app/admin/page.tsx` h1 and `CheckoutForm` section h2s exactly |
| Display | 24px (`text-2xl`) | 600 (semibold) | 1.2 — reused deliberately at the same size as Heading for emphasis numbers (order grand total on the detail view), matching `OrderSummaryLines`'s existing `text-2xl font-semibold` total treatment. Admin has no marketing-scale type and no KPI dashboard (analytics is v2/out of scope per REQUIREMENTS), so a fifth larger size would be unused — do not introduce one. |

Micro text (12px, `text-xs`) is used ONLY for timestamps, meta captions, and uppercase micro-labels
(e.g. "Page 3 of 8", relative order dates) — always paired with 14px primary content on the same
row, never standalone as the only text at a given hierarchy level.

Exactly 2 weights used across the whole phase: **400 regular** (descriptive/secondary copy) and
**600 semibold** (everything actionable or structural: labels, headings, buttons, badges, table
headers). No `font-bold`/`font-extrabold` — those are storefront marketing flourishes
(`ProductCard` price, `SiteHeader` brand mark) that don't belong in a functional owner tool.

## Color

| Role | Value | Usage |
|------|-------|-------|

| Secondary (30%) | `var(--surface)` → `#ffffff` light / `#131320` dark (`bg-surface`), plus `var(--border)` → `#e7e7ee` / `#26263a` for hairlines | Sidebar, header bar, table containers, section cards (`rounded-2xl bg-surface border border-border`, identical to `CheckoutForm` section pattern) |
| Accent (10%) | `var(--brand)` → `#4f46e5` indigo-600 light / `#818cf8` indigo-400 dark (`bg-brand` / `text-brand` / `ring-brand`) | Reserved for: (1) primary CTA buttons — "Add product", "Save product", "Advance to [next status]", "Confirm bank transfer"; (2) the active sidebar nav item (left border/background wash `bg-brand-soft`); (3) focus rings on all interactive elements (`focus-visible:ring-brand`); (4) the ON state of the payment-method toggle switch track; (5) the "processing" order-status badge. **Never** used as a large background fill or default text color. |
| Destructive | `var(--stock-out)` → `#dc2626` red-600 light / `#f87171` red-400 dark (`text-stock-out`, paired with `bg-red-50 border-red-200` tint per the existing `OOSWarningBanner`/`CheckoutForm` error-banner pattern) | Reserved for: "Deactivate product" button + confirmation, "Cancel order" action, delete-image icon button, form validation error text, the "payment_failed" status badge, all error banners. This reuses the exact token already doing double duty for stock-out and form-error red in Phases 2–4 — no new red is introduced. |

Accent reserved for: primary CTA buttons, active nav indicator, focus rings, ON-state toggle
track, and the "processing" status badge only. It is never used for informational surfaces, table
zebra striping, or default link color (links inside admin body copy use `text-brand
hover:text-brand-strong` exactly as `EmptyState.tsx` does, which is the one exception already
established store-wide for hyperlinks — kept for consistency, not a new accent surface).

### Order status badge palette (8 states — SC3, D-08)

Every badge renders **icon + text label**, never a color-only dot, satisfying "don't rely on color
alone." All badges share one shape: `inline-flex items-center gap-1.5 rounded-full border px-2.5
py-1 text-sm font-semibold` (pill, 14px semibold label, matches the Label typography row).

| Status | Badge classes | Icon (Heroicons, 14px) | Label text |
|--------|---------------|------------------------|------------|
| `pending_payment` | `bg-zinc-100 text-zinc-700 border-zinc-200 dark:bg-zinc-800 dark:text-zinc-300 dark:border-zinc-700` | ClockIcon | "Pending payment" |
| `awaiting_bank_transfer` | `bg-amber-50 text-amber-800 border-amber-200 dark:bg-amber-500/10 dark:text-amber-300 dark:border-amber-500/30` (exact tint already used by `OOSWarningBanner`) | BuildingLibraryIcon | "Awaiting bank transfer" |
| `payment_confirmed` | `bg-teal-50 text-teal-700 border-teal-200 dark:bg-teal-500/10 dark:text-teal-300 dark:border-teal-500/30` | CheckCircleIcon | "Payment confirmed" |
| `processing` | `bg-brand-soft text-brand-strong border-brand/30` (the one status that uses the brand accent — signals "admin action in flight") | ArrowPathIcon | "Processing" |
| `shipped` | `bg-sky-50 text-sky-700 border-sky-200 dark:bg-sky-500/10 dark:text-sky-300 dark:border-sky-500/30` | TruckIcon | "Shipped" |
| `delivered` | `bg-green-50 text-green-700 border-green-200 dark:bg-green-500/10 dark:text-green-300 dark:border-green-500/30` (green = `--stock-in` family, the terminal-success color) | CheckBadgeIcon | "Delivered" |
| `cancelled` | `bg-zinc-200 text-zinc-800 border-zinc-300 dark:bg-zinc-700 dark:text-zinc-200 dark:border-zinc-600` (darker neutral — intentional stop, not an error) | XCircleIcon | "Cancelled" |
| `payment_failed` | `bg-red-50 text-stock-out border-red-200 dark:bg-red-500/10 dark:border-red-500/30` (Destructive token) | ExclamationCircleIcon | "Payment failed" |

Rationale for the palette: `--stock-in/low/out` tokens stay reserved for literal stock-level
semantics elsewhere in the app; order-status badges borrow adjacent Tailwind hues (teal, sky,
zinc) so the two systems never visually collide (e.g., a green "Delivered" order badge must not
look like a green "In stock" pill in the same admin session).

### Product / variant active state

- Active: `bg-green-50 text-green-700 border-green-200` pill, label "Active" (reuses the delivered
  hue family — "currently live" semantics).
- Deactivated (soft-deleted, D-04): `bg-zinc-100 text-zinc-500 border-zinc-200` pill, label
  "Deactivated" — neutral, not destructive-red, because deactivation is reversible and intentional,
  not an error state.

## Surfaces

### 1. Admin shell (layout — grows from `src/app/admin/page.tsx`)

**Structure:** `src/app/admin/layout.tsx` wraps all `/admin/*` routes.
- Desktop (≥1024px, `lg:`): fixed-width **240px sidebar** (`bg-surface border-r border-border`) +
  fluid content area. Sidebar contains: brand mark (reuse the `SiteHeader` indigo bolt mark at
  smaller scale, links to `/admin`), nav list (Products / Orders / Settings), and a
  bottom-pinned "Signed in as {email}" + "Sign out" block (reusing the exact button classes
  already in `src/app/admin/page.tsx`).
- Tablet/mobile (`<1024px`): sidebar collapses to a **top header bar** (`bg-surface border-b
  border-border`, sticky, `h-16`, matching `SiteHeader`'s sticky pattern) with a hamburger
  trigger that opens the same nav list in a slide-over drawer (reuse `ProductFilters`' mobile
  drawer pattern: `fixed inset-0 z-50`, backdrop `bg-black/40`, panel `role="dialog"
  aria-modal="true"`).
- Nav item states: default `text-muted hover:text-foreground hover:bg-brand-soft/50`; active route
  `bg-brand-soft text-brand-strong font-semibold` with a 2px left border in `bg-brand` (`border-l-2
  border-brand`) — the "active nav indicator" use of the 10% accent.
- Content area: `max-w-7xl` (wide tables need room, unlike the storefront's `max-w-5xl`), `px-6
  lg:px-8 py-8`.
- Every admin page renders inside a `<Suspense>` boundary around the auth-gated content, exactly
  as `src/app/admin/page.tsx` already does (dynamic session check stays out of the static shell).

**States:** No loading/empty/error states at the shell level — it always renders (auth redirect
happens in `proxy.ts`/`verifyAdminSession()` before content mounts).

### 2. Products list (`/admin/products`)

**Layout:** Section heading "Products" (24px) + primary CTA "Add product" (brand button,
top-right) + search input (reuse `SearchBar`'s input styling) + a status filter chip pair
("All" / "Active" / "Deactivated") above a table.

**Table columns** (`bg-surface rounded-2xl border border-border` wrapping a `<table>`, 20px
horizontal cell padding per the spacing exceptions):
Name (with 40×40px thumbnail, reusing the `bg-zinc-100` + Heroicons `PhotoIcon` placeholder from
`ProductCard`/`CartLineItem`) · Category · Brand · Variants (count) · Price range (formatted via
`formatNGN`, "₦X,XXX – ₦Y,YYY" or single value if one variant) · Stock (sum across variants, using
the same tiered `StockIndicator` color logic: green "In stock" / amber "Low stock" / red "Out of
stock") · Status (Active/Deactivated pill) · Row actions (Edit — brand text link; Deactivate/
Reactivate — overflow menu, `EllipsisVerticalIcon`, red text for Deactivate).

**States:**
- Loading: skeleton rows (`animate-pulse bg-zinc-100 dark:bg-zinc-800` blocks in each cell),
  matching the shell's `animate-pulse` Suspense fallback pattern.
- Empty (no products at all): centered `EmptyState`-pattern block — "No products yet" copy +
  "Add product" CTA (reuses `EmptyState.tsx` layout: centered icon (`CubeIcon`), heading, body,
  link/button).
- Empty (filtered, zero matches): "No products match your filters" + "Clear filters" link,
  identical structure to the catalog's `EmptyState hasFilters` variant.
- Error (query failure): red banner above the table, "Couldn't load products" + "Try refreshing
  the page."

### 3. Product editor (`/admin/products/new`, `/admin/products/[id]/edit`)

**Layout:** Single-column stacked section cards (`rounded-2xl bg-surface border border-border p-6
space-y-6` between sections) — directly mirrors `CheckoutForm`'s section-card rhythm so the admin
editor feels like a sibling of checkout, not a different app.

1. **Details card:** Name, Slug (auto-generated from name, editable, helper text "Used in the
   product URL — must be unique"), Description (textarea), Category (select, seeded 3 values),
   Brand (select or "+ Add new brand" inline option).
2. **Images card:** Grid of uploaded images (square thumbnails, drag-to-reorder position later —
   v1 just shows position number), each with a **required** Alt text input directly beneath its
   thumbnail (`inputClass`-styled, red validation border + "Alt text is required" error if blank
   on save attempt — client hint only; D-03 requires server-side enforcement regardless). "Set as
   primary" radio per image. "Add images" drop zone (dashed `border-2 border-dashed border-border
   rounded-xl`, `BuildingLibraryIcon`-style upload icon, "Drag images here or click to upload —
   JPG, PNG, or WebP, up to 5MB each").
3. **Variants card:** One row per variant (D-05), each row = option-value chips (e.g. "Black ·
   256GB") + Price input (₦, `inputClass`, kobo stored/converted at the boundary — the input
   itself shows naira, never raw kobo) + Stock input (number) + Active toggle (small switch) +
   remove icon button (`TrashIcon`, matches `CartLineItem`'s trash button styling exactly,
   44×44px target). "+ Add variant" button below the list opens an inline option-value picker
   (checkboxes per product option) then appends a row.
4. **Footer action bar:** sticky bottom bar (`border-t border-border bg-surface/95 backdrop-blur
   px-6 py-4`) — "Save changes"/"Create product" (brand, right-aligned) + "Deactivate product"
   (red text button, left-aligned, edit mode only, opens the destructive confirm dialog) +
   "Cancel" (neutral text link, right of Save, `text-muted hover:text-foreground`).

**States:**
- Loading (edit mode, fetching existing product): full-card skeletons per section.
- Saving: Save button shows the existing spinner pattern from `CheckoutForm`'s "Place order"
  button (`ArrowPathIcon animate-spin` + "Saving…"), disabled + `aria-disabled`.
- Validation error: inline field errors (see Copywriting Contract), page does not navigate away —
  matches the checkout "stay on page on failure" rule (D-08 precedent).
- Save failure (server/network): red banner at the top of the form, matching `CheckoutForm`'s
  bank-transfer error banner exactly (`bg-red-50 border-red-200`, `ExclamationCircleIcon`).
- Save success: redirect to Products list with a one-shot success toast/banner
  (`bg-green-50 border-green-200 text-green-700`, "Product saved") — dismissible, auto-hides.
- Cache invalidation (D-06) is a server-side effect, not a visible UI state — no spinner needed
  beyond the normal Save-pending state; the PDP simply reflects fresh data on next load.

### 4. Orders list (`/admin/orders`)

**Layout:** Heading "Orders" (24px) + status filter as a horizontal pill/segmented control
listing all 8 statuses plus "All" (reusing the Order Status Badge visual language for each pill,
active pill gets `ring-2 ring-brand`) above a table.

**Table columns:** Reference (e.g. "MS-A1B2C3", monospace-ish via `font-mono` for scanability) ·
Date (relative + absolute on hover title) · Customer email · Total (`formatNGN`) · Payment method
(small icon reused from `PaymentMethodSelector`'s method icon set + label) · Status (badge from
the palette above) · row is a full-row `<Link>` to the order detail (reuses `ProductCard`'s

table semantics).

**States:**
- Loading: skeleton rows, same pattern as Products list.
- Empty (no orders): "No orders yet" + body copy, no CTA (nothing to create — orders come from
  customers).
- Empty (filtered): "No orders with this status" + "View all orders" link.
- Error: same red banner pattern as Products list.

### 5. Order detail (`/admin/orders/[id]`)

**Layout:** Two-column on desktop (`lg:grid lg:grid-cols-[1fr_360px] lg:gap-8`), stacked on
mobile — mirrors the `/order/[token]` confirmation page's split (`OrderSummaryLines` +
`ShippingAddressBlock` in a sidebar column), reusing those exact components read-only.

- **Header:** "Order {reference}" (24px heading) + current status badge beside it + placed-on
  date.
- **Left column:** Line items via `OrderSummaryLines` (reused verbatim — product name, variant
  label, qty, line total, subtotal/shipping/total) + Payment details card (method, gateway
  provider/reference or Stripe PI id, paid-at timestamp if set).
- **Right column (sidebar):** `ShippingAddressBlock` (reused verbatim) + **Fulfillment card**:
  current status badge (large, `text-base` variant of the pill) + a **guided transition
  control** — NOT a dropdown. Renders one button per legal next state returned by the server
  (`getValidNextStatuses(currentStatus)` — exact transition graph is planner territory per D-08 /
  Claude's Discretion; the UI contract only requires that whatever the server returns renders as
  a **primary button per option**, e.g. "Mark as Processing", "Mark as Shipped", "Cancel order"
  as a secondary/red option when cancellation is legal from that state). Terminal states
  (`delivered`, `cancelled`) render no transition buttons, just a "This order is complete." /
  "This order was cancelled." muted note instead.
- **Bank-transfer special case:** when `status === "awaiting_bank_transfer"`, the Fulfillment
  card's primary action is **"Confirm payment received"** (not a generic transition button) —
  visually distinct with a small `BuildingLibraryIcon` and helper text "Routes through the same
  confirmation path used for card payments — stock will be decremented and the customer will be
  emailed." This visibly signals "same path as the webhook" per the phase's specific-idea intent.

**States:**
- Loading: skeleton for the whole two-column layout.
- Transition pending: the clicked button shows the spinner pattern (`ArrowPathIcon animate-spin`
  + "Updating…"), all other transition buttons disabled during the pending transition (prevent
  double-submit / race).
- Transition success: status badge updates in place (no full page reload needed if using a
  Server Action + revalidation), plus a small inline success note "Marked as {status}. {Customer
  email} was notified." shown ONLY when the transition was `shipped` or `delivered` (D-10 — no
  email on other transitions, and the UI should not claim an email was sent when it wasn't).
- Transition error: red banner, "That status change isn't allowed" or the specific server error
  (e.g. confirm-order-paid's oversold-refund path returning a message) — order detail does not
  navigate away.
- 404 (bad order id): full-page not-found treatment reusing the empty-state icon/heading pattern,
  "Order not found" + link back to Orders list.

### 6. Settings (`/admin/settings`)

**Layout:** Heading "Settings" (24px) + a single "Payment methods" section card containing one
row per method: Stripe, PayPal, Bank transfer (D-11's SC5 scope — exactly these three; NG
gateways are NOT shown here per the deferred-idea note).

**Row anatomy** (each row `flex items-center justify-between py-4 border-b border-border
last:border-0`):
- Left: method icon (reuse `PaymentMethodSelector`'s icon set) + label + one-line description
  (e.g. "Debit / credit cards via Stripe").
- Right: a **toggle switch** — new component, no existing precedent in the codebase, so it is
  specified fully here:
  - Track: `w-11 h-6 rounded-full transition-colors` — OFF: `bg-zinc-300 dark:bg-zinc-600`; ON:
    `bg-brand` (the one deliberate large-ish accent-colored surface in the whole phase — a toggle
    track is a control, not a background, so this doesn't violate the "accent never a large fill"
    rule, which is about page/section backgrounds).
  - Thumb: `w-5 h-5 rounded-full bg-white shadow`, translates via `translate-x-0` /
    `translate-x-5`.
  - Focus: `focus-visible:ring-2 focus-visible:ring-brand focus-visible:ring-offset-2` on the
    track (role="switch", `aria-checked`).
  - Below each row, when the DB flag is ON but server credentials are missing (D-11's dual gate):
    an amber inline note (see Copywriting Contract "disabled-credentials note") with a small
    `ExclamationTriangleIcon`, reusing `OOSWarningBanner`'s amber tint but inline (not a full
    banner) — `text-sm text-amber-700 dark:text-amber-400 mt-1`.
  - PayPal row is always rendered but effectively inert per D-05a — an additional muted note
    "PayPal doesn't support NGN yet — this toggle has no effect until enabled." sits under it
    permanently, distinguishing it from the credential-missing note (this is a scope note, not a
    misconfiguration warning).

**States:**
- Toggling: the switch shows a brief disabled/opacity-60 state during the Server Action round
  trip (sub-second; no separate spinner needed for a binary switch — the thumb position change
  itself is the feedback once the action resolves). If the action fails, the switch snaps back to
  its previous position and a red inline note appears: "Couldn't update this setting. Try again."
- No empty/error states beyond the above — the three rows always render (seeded `store_settings`
  rows per D-11's scope note).

## Interaction Rules (cross-surface)

- **Forms:** `react-hook-form` + `zod`, `mode: "onBlur"`, matching `CheckoutForm` exactly. All
  inputs use the shared `inputClass(hasError)` helper (border `border-border` default, ring+border
  `border-stock-out ring-2 ring-stock-out` on error) — copy this helper into an admin-shared module
  rather than reimplementing it.
- **Destructive actions always confirm** via a modal dialog (`role="dialog" aria-modal="true"`,
  backdrop `bg-black/40`, reusing `ProductFilters`' mobile-drawer modal shell adapted to a centered
  card instead of a bottom sheet): Deactivate product, Remove variant (only if it has an id /
  already saved), Cancel order.
- **Non-destructive-but-irreversible actions** (Confirm bank transfer) also confirm, but the
  confirm button is brand-colored, not red — irreversibility ≠ destructiveness in this system.
- **No raw status dropdowns anywhere.** Every status change in the UI is a labeled button naming
  its destination state, sourced from a server-provided list of legal transitions (D-08).
- **Every mutating action is a Server Action, auth-checked server-side first** (D-02) — the UI
  never assumes success; buttons disable during `useTransition` pending state exactly as
  `CartLineItem`'s remove button and `CheckoutForm`'s submit button already do.
- **Toasts/banners auto-dismiss** after ~4s for success, persist until dismissed or retried for
  errors — consistent with there being no existing toast library; implement as a simple fixed-
  position banner component, not a new dependency.

## Accessibility Contracts

- All icon-only buttons have `aria-label` (Deactivate, Remove image, Remove variant, Close
  drawer) — matching the existing pattern in `CartLineItem`/`ProductFilters`.
- All form errors use `role="alert"` + `aria-invalid` + `aria-describedby` wired to the error
  message id, exactly as `CheckoutForm` does field-by-field.
- Status badges are never color-only — text label is always present in the DOM, not just a
  `title` attribute.
- Toggle switches use `role="switch"` + `aria-checked`, not a bare checkbox styled to look like a
  switch without the role.
- Guided transition buttons and the destructive/irreversible confirm dialogs are fully keyboard
  operable (`Tab`/`Enter`/`Escape` closes dialogs), matching the existing mobile filter drawer's
  keyboard behavior expectations.
- Minimum touch target 44×44px for all icon-only interactive elements (spacing exception noted
  above), even though admin is desktop-first — SC/D-01 requires it not break on mobile/tablet.
- Focus rings use `focus-visible:ring-2 focus-visible:ring-brand focus-visible:ring-offset-2`
  everywhere, zero exceptions — this is already a house rule across every reviewed component.
- Color contrast: all badge tint/text pairs above are drawn from Tailwind's 50/700 or 500/10
  (dark)/300 pairings already used elsewhere in the codebase for AA-compliant text-on-tint
  contrast (e.g. `amber-50`/`amber-800`, `red-50`/`text-stock-out`).
