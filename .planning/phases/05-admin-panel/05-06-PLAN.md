<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| admin UI → order/settings Server Actions | UI renders only legal options; server re-verifies + re-validates |
| settings page → env credentials | Credential presence read server-side, never exposing secret values |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-22 | Tampering | Illegal status jump offered by the UI | mitigate | OrderStatusControl renders only server-supplied getValidNextStatuses; no `<select>`; server still rejects via LEGAL_TRANSITIONS (Plan 04) |
| T-05-23 | Information Disclosure | Settings page leaking secret credential VALUES | mitigate | Only a boolean "credentials present" is computed server-side and passed down; the secret value never reaches the client |
| T-05-24 | Tampering / Elevation | Toggle change accepted from a non-admin client | mitigate | toggleStoreSetting re-verifies admin server-side (Plan 04); UI switch is not the enforcement point |
| T-05-25 | Elevation of Privilege | Reaching admin pages while logged out | mitigate | proxy.ts redirect + layout verifyAdminSession (Plan 05); verified in checkpoint step 4 |
</threat_model>
