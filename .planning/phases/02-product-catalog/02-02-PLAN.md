<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client (URL searchParams) → Server Component → DB | Untrusted: q, brand, minPrice, maxPrice, sort, page arrive from the URL and feed DB queries. |
| server → rendered HTML | Search term `q` is echoed into the results heading. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-04 | Tampering | getCatalog (searchParams → SQL) | mitigate | All filters use Drizzle parameterized operators (ilike/eq/gte/lte) — never string-concatenation into SQL. Inputs pre-validated/clamped by parseCatalogParams (zod). Severity: HIGH → mitigated to LOW. |
| T-02-05 | Tampering (XSS) | search page heading echoing `q` | mitigate | `q` rendered only as a React text node (auto-escaped); never via dangerouslySetInnerHTML, never into an attribute/URL. Search term length capped at 100. Severity: MEDIUM → mitigated. |
| T-02-06 | Denial of Service | page/minPrice/maxPrice unbounded | mitigate | parseCatalogParams clamps page (1..1000), price (0..1e9), q length (≤100), and PAGE_SIZE is fixed at 24. Severity: MEDIUM → mitigated. |
| T-02-07 | Tampering (open redirect) | SearchBar / search `q` | mitigate | `q` is only a DB filter string; never used in any redirect target. router.push targets are fixed literal paths. Severity: LOW. |
| T-02-08 | Information Disclosure | NEXT_PUBLIC / secrets in client comps | accept | SearchBar/SortSelect/ProductFilters carry no secrets and no price computation; price comes from server queries only. Severity: LOW. |

No unmitigated HIGH-severity threats: SQLi (T-02-04) is mitigated by parameterized queries + zod clamps before this plan completes.
</threat_model>
