<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| product content (DB text) → rendered JSON-LD `<script>` | Product name/description (which an admin will control in Phase 5) is serialized into an inline script tag. |
| cache layer → customer | Cached content must never cache stock/price as stale-positive availability. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-12 | Tampering (XSS) | JSON-LD `<script>` injection | mitigate | `JSON.stringify(jsonLd).replace(/</g, "\\u003c")` per official Next.js pattern — neutralizes a `</script>` breakout in any product field. Severity: MEDIUM → mitigated. |
| T-02-13 | Information Disclosure / Integrity | over-caching stock as "InStock" | mitigate | Stock/price block carries NO 'use cache'; only static content is cached (cacheLife hours + cacheTag). SC5 manual verification confirms stock reflects DB edits immediately. Severity: MEDIUM → mitigated. |
| T-02-14 | Spoofing | wrong canonical domain | accept | metadataBase uses NEXT_PUBLIC_BASE_URL with a dev placeholder; production domain set at deploy time (user_setup). Severity: LOW (dev-only placeholder). |

No HIGH-severity threats. The two MEDIUM threats (JSON-LD XSS, stale-stock over-caching) are explicitly mitigated within this plan.
