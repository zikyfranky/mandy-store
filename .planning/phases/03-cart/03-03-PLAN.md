<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → cart Server Action | Stepper/remove/add calls cross from the browser into Server Actions (validated in Plan 02) |
| server cart → client drawer | getCart output (already price-safe, OOS-flagged) is rendered, not recomputed client-side |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-11 | Tampering | CartStepper/CartLineItem mutations | mitigate | UI only submits {variantId, newQty}; all clamping/validation happens in Plan 02 Server Actions (`clampToStock`, Zod). The client cannot bypass stock caps — plus is disabled at stock and the server re-clamps regardless. |
| T-03-12 | Tampering | drawer/page subtotal display | mitigate | Subtotal/line totals come straight from getCart (computed from variants.priceKobo); the client never computes or submits a total (SC4). |
| T-03-13 | Denial of service | rapid stepper clicks | mitigate | useTransition disables +/- during flight; server `onConflictDoUpdate` + clamp are the final guard (research Pitfall 5). |
| T-03-14 | Information disclosure | CartProvider client cart state | accept | Drawer holds only variantId/quantity/label/price-for-display (already public catalog prices) — no PII, no secrets exposed beyond what the catalog already shows. |
</threat_model>
