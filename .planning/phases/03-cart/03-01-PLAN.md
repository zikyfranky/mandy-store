<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → cart cookie | Guest browser holds the cart cookie; its contents are attacker-controllable |
| cart_item row → variants | Cart references must resolve to real, active variants before any total is computed |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering | cart_item / cookie schema | mitigate | Schema has NO price column; `hydrateCart` computes lineTotalKobo only from `variants.priceKobo` — prices can never be supplied by the client (SC4, CLAUDE.md). Acceptance criterion greps that cart_item has no priceKobo. |
| T-03-02 | Tampering | parseCartCookie | mitigate | Malformed/forged cookie JSON is caught (try/catch + Array.isArray + per-field typeof filter) and degrades to `[]`; tested in cart-logic.test.ts. |
| T-03-03 | Tampering | hydrateCart (forged variantId) | mitigate | Items whose variantId is absent from the server-fetched variantRows are dropped; quantities clamped to `variants.stock` (D-06/D-12). |
| T-03-04 | Information disclosure | cart_item table | accept | Stores only {variantId, quantity} — no PII, no prices, no secrets; nothing sensitive to leak. |
</threat_model>
