# Phase 3 — UI Design Contract: Cart

> Visual and interaction contract for Phase 3 frontend surfaces. Generated by gsd-ui-researcher.
> This phase EXTENDS the Phase 2 design system — all tokens, typography, and color are inherited.
> No new design system is introduced.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Tailwind v4 only — matches Phase 2; no shadcn) |
| Preset | not applicable |
| Component library | none — custom-styled primitives with Tailwind v4 utility classes |
| Icon library | Heroicons v2 (SVG, inline — same as Phase 2) |
| Font | Geist Sans (`var(--font-geist-sans)` — already loaded in `src/app/layout.tsx`) |
| New dependency | `focus-trap-react@12.0.2` — keyboard focus trap for cart drawer (RESEARCH.md §Standard Stack) |

**Rationale:** Phase 2 established a complete Tailwind v4 design system. Phase 3 inherits every token verbatim. The only addition is `focus-trap-react` for accessible drawer keyboard trapping — this is a behavior dependency, not a UI component library.

**Source:** globals.css (--brand, --brand-strong, --brand-soft, --hot, .brand-gradient, .no-scrollbar), 02-UI-SPEC.md (all spacing, typography, color, component patterns).

## Spacing Scale

Declared values — INHERITED from Phase 2, multiples of 4 only:

| Token | Value | Cart Usage |
|-------|-------|-----------|
| xs | 4px | Gap between stepper icon and count, badge padding, swatch offset |
| sm | 8px | Line-item internal gaps (image-to-text), stepper button padding, icon button touch-target offset |
| md | 16px | Cart drawer body padding (`p-4`), line-item vertical padding, `/cart` page content padding |
| lg | 24px | Drawer header padding, section separator margin, `/cart` page column gap |
| xl | 32px | Drawer max-width breakout guard on desktop, `/cart` outer padding on desktop (`px-8`) |
| 2xl | 48px | `/cart` page vertical padding above line items on desktop |
| 3xl | 64px | Not used in Phase 3 |

Exceptions:
- Cart drawer width: 400px on `≥640px`; full-width (`w-full`) on `<640px`
- Stepper buttons (− / +): minimum 36×36px touch target (`min-h-9 min-w-9`)
- Trash/remove icon button: minimum 44×44px touch target (`min-h-11 min-w-11`) — matches Phase 2 icon button standard
- Cart line-item thumbnail: 72×72px (`w-18 h-18` = Tailwind `size-18`) with `rounded-xl object-cover`

## Typography

INHERITED from Phase 2 — 4-size scale, 2 weights, no additions:

| Role | Size | Weight | Line Height | Tailwind Class | Cart Usage |
|------|------|--------|-------------|----------------|-----------|
| Body | 16px | 400 (regular) | 1.5 | `text-base font-normal leading-relaxed` | Drawer/page prose, variant option labels on line items |
| Label | 14px | 600 (semibold) | 1.4 | `text-sm font-semibold leading-snug` | Line-item product name, stepper quantity count, unit price, badge count, drawer subtotal label, clamp notice |
| Heading | 24px | 600 (semibold) | 1.3 | `text-2xl font-semibold leading-tight` | `/cart` page heading ("Your cart"), cart drawer title ("Cart") |
| Display | 28px | 600 (semibold) | 1.2 | `text-3xl font-semibold leading-tight` | Not used in Phase 3 |

**Weights in use: exactly 2 — 400 (regular) and 600 (semibold). No font-medium (500) or font-bold (700).**

Special cases within the 4-step scale:
- Subtotal amount (drawer footer + `/cart` order summary): `text-2xl font-semibold` (24px, 600) — uses the existing Heading tier so the key number reads prominently without adding a new size to the Phase 2 scale (14/16/24/28).
- Badge count inside the rose bubble: `text-[10px] font-semibold` — documented micro-numeral exception (count bubble only; same role as a spacing touch-target exception). Weight is 600 to honor the 2-weight rule; update the existing `SiteHeader.tsx` stub from `font-bold` to `font-semibold` when wiring the live count.

### 1. Cart Drawer (mini-cart) — D-01, D-03

**Trigger:** Clicking "Add to cart" on PDP, OR clicking the cart icon in `SiteHeader`.

**Layout:**
```
[overlay: fixed inset-0 bg-black/40 backdrop-blur-sm z-50]
  [panel: fixed right-0 inset-y-0 w-full sm:w-[400px] bg-surface z-50
          shadow-2xl flex flex-col
          translate-x-full → translate-x-0 transition-transform duration-300 ease-out]
    [header: px-5 py-4 flex items-center justify-between border-b border-border]
      [title: text-2xl font-semibold]  "Cart"
      [close button: min-h-11 min-w-11 rounded-full hover:bg-brand-soft — X icon 24px]
    [line-item list: flex-1 overflow-y-auto py-2 .no-scrollbar]
      [CartLineItem × N]
    [footer: px-5 py-4 border-t border-border bg-surface space-y-4]
      [subtotal row: flex justify-between items-baseline]
        [label: text-sm font-semibold text-muted]  "Subtotal"
        [amount: text-2xl font-semibold text-foreground]  "₦XX,XXX.XX"
      [shipping note: text-sm text-muted text-center]  "Shipping calculated at checkout"
      [Checkout button: w-full rounded-xl bg-brand hover:bg-brand-strong text-white
                        px-6 py-4 text-base font-semibold transition-colors]
        "Checkout"
      [View cart link: w-full text-center text-sm font-semibold text-brand hover:text-brand-strong]
        "View full cart"
```

- Drawer overlays the page; page content is NOT scrollable while drawer is open (overflow-hidden on body via CartProvider)
- Focus trapped inside drawer using `focus-trap-react@12.0.2` when open
- Escape key closes drawer (handled by focus-trap-react `onDeactivate`)
- Open animation: `translate-x-full → translate-x-0`, 300ms, `ease-out`
- Close animation: `translate-x-0 → translate-x-full`, 300ms, `ease-in`
- Overlay fades in/out: `opacity-0 → opacity-100`, 200ms, `ease-out`
- On mobile (`<640px`): drawer is full-width; same structure applies
- Checkout button: Phase 4 placeholder this phase — disabled state: `opacity-50 cursor-not-allowed` with `title="Checkout coming soon"` — OR fully functional href stub to `/cart` as an intermediate (Claude's Discretion; default: keep enabled, route to `/cart` for now — Phase 4 upgrades to real checkout)

**OOS gate (D-11):** If `hasOOS === true`, Checkout button is disabled: `disabled opacity-50 cursor-not-allowed` with aria-label "Remove out-of-stock items to proceed".

### 3. Quantity Stepper — D-04, D-06, D-07

`CartStepper` — Client Component. Used inside `CartLineItem`.

```
[stepper: inline-flex items-center rounded-full border border-border bg-surface h-9]

  [minus button: min-h-9 min-w-9 flex items-center justify-center rounded-full
                 text-foreground hover:bg-brand-soft transition-colors
                 disabled:opacity-40 disabled:cursor-not-allowed]
    [Heroicons MinusIcon 16px]
    aria-label="Decrease quantity"

  [count: text-sm font-semibold text-foreground min-w-[2rem] text-center px-1]
    {quantity}  (e.g. "2")

  [plus button: min-h-9 min-w-9 flex items-center justify-center rounded-full
                text-foreground hover:bg-brand-soft transition-colors
                disabled:opacity-40 disabled:cursor-not-allowed]
    [Heroicons PlusIcon 16px]
    aria-label="Increase quantity"
```

- Minus at `quantity === 1`: clicking removes the item (D-07) — no confirmation; trash icon provides an explicit alternate removal path
- Minus at `quantity === 0`: never rendered (item removed before reaching 0)
- Plus at `quantity === stock`: disabled (D-06); shows cap message below stepper: `text-sm font-semibold text-amber-600 dark:text-amber-400` — "Only {N} available"
- OOS item (stock === 0): entire stepper disabled (`opacity-40 pointer-events-none`)
- During pending server action: `useTransition` + `isPending` — both +/- buttons disabled; add `animate-pulse` to count text; no spinner overlay
- Debounce: not needed if `useTransition` gates interaction; if rapid clicks bypass the gate, the server action's `Math.min(qty, stock)` cap is the last line of defense

## Interaction Contracts

### Cart Drawer Open/Close

1. Drawer closed by default (`isOpen: false` in CartProvider)
2. Click "Add to cart" on PDP → server action fires → on success, `CartProvider.open()` called immediately (optimistic)
3. Click header cart icon → `CartProvider.open()` called immediately (no server round-trip)
4. Click overlay (outside drawer panel) → `CartProvider.close()`
5. Press Escape → `CartProvider.close()` (via focus-trap-react `onDeactivate`)
6. Click drawer X button → `CartProvider.close()`
7. Focus returns to the element that triggered open (focus-trap-react `returnFocusOnDeactivate`)

### Add to Cart Flow (PDP)

1. User selects a valid, in-stock variant on PDP
2. "Add to cart" button enabled; user clicks
3. Button enters `isPending` state: label "Adding…" with spinner; button disabled
4. `addToCart(variantId, 1)` Server Action executes:
   - Validates input via Zod
   - Reads variant stock from DB (server-side, D-06)
   - Writes cookie (guest) or DB cart_item (authed)
   - Calls `revalidatePath('/', 'layout')`
   - Returns `{ success, count }`
5. Client receives result:
   - `setOptimisticCount(count)` — badge updates immediately
   - `CartProvider.open()` — drawer slides in
6. Button exits `isPending`; returns to "Add to cart" idle state
7. User reviews cart in drawer; clicks "View full cart" to go to `/cart` or "Checkout" (Phase 4 placeholder)

### Stepper Mutation Flow

1. User clicks + or − on a line item (drawer or `/cart` page)
2. Stepper enters `isPending`: both +/- disabled, count text `animate-pulse`
3. `updateCartItem(variantId, newQty)` Server Action executes:
   - If `newQty === 0`: calls `removeCartItem(variantId)` instead (D-07)
   - Validates qty against stock (D-06)
   - Writes cookie or DB
   - Calls `revalidatePath('/', 'layout')`
4. Page/drawer re-renders with updated cart from server
5. If clamped: `isClamped === true` on the hydrated line → clamp notice appears (D-12)

### Remove Item Flow

1. User clicks trash icon on a line item
2. `removeCartItem(variantId)` Server Action fires immediately (no confirmation dialog)
3. Item disappears from list after server re-render
4. If cart becomes empty: empty state renders (D-14)
5. If the removed item was the last OOS item: Checkout button re-enables

### Login Merge Flow (D-10) — visual contract only

1. Guest adds items to cart (drawer shows items normally)
2. Guest navigates to login and authenticates
3. `login()` Server Action calls `mergeGuestCartOnLogin(userId)` — additive merge, clamped to stock
4. After redirect: cart shows merged items seamlessly
5. No visual "merge" animation or notification required — the cart just contains the right items

## Accessibility Contracts

- Cart drawer: `role="dialog"` `aria-modal="true"` `aria-label="Shopping cart"` `aria-labelledby={drawerTitleId}`
- Cart drawer: keyboard focus trapped by `focus-trap-react@12.0.2`; first focusable element on open is the close (X) button; Escape closes
- Cart drawer overlay: `aria-hidden="true"` (decorative; drawer panel is the semantic element)
- Stepper: wrapped in `role="group"` `aria-label="Quantity for {product name}"`; count element has `aria-live="polite"` `aria-atomic="true"` so screen readers announce qty changes
- OOS line item: `aria-disabled="true"` on stepper; `aria-label="Out of stock — {product name}"`
- Clamp notice: `role="status"` `aria-live="polite"` — announces automatically when it appears
- Badge count: updates via CartProvider `optimisticCount`; `aria-label` on the cart button includes live count
- Empty state heading: `<h2>` (not `<p>`)
- Thumbnail images: `alt={productName}` (short, factual — no "image of" prefix)
- All interactive elements: `focus-visible:ring-2 focus-visible:ring-brand focus-visible:ring-offset-2` — matches Phase 2 pattern with indigo instead of blue-600
- `/cart` page: `<main>` wrapper, heading is `<h1>`; order summary heading is `<h2>`
