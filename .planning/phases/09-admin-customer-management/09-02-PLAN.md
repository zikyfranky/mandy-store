<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client island → Server Action | untrusted `userId`/`newRole`/reset payload crosses into privileged mutations |
| public browser → resetPassword | unauthenticated caller submits `{email,token,password}` |
| verificationTokens table (shared) | verify and reset tokens coexist with no `type` column |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-02 | Elevation of Privilege | `updateCustomerRole` | mitigate | verifyAdminSession() first; reject self (`userId===admin.id`); atomic last-admin conditional UPDATE (COUNT>1) — no TOCTOU (D-04, Pitfall 4) |
| T-09-03 | Spoofing | reset link replay | mitigate | Single-use delete-on-consume; 1h expiry check with delete; delete-prior-token keeps exactly one live link (D-07.2, Pitfall 3) |
| T-09-04 | Spoofing | verify↔reset token misuse | mitigate | resetPassword enforces `pwreset_` prefix; verifyEmail rejects `pwreset_` prefix (D-07.3, Pitfall 2) |
| T-09-05 | Elevation of Privilege | session survives reset | mitigate | resetPassword deletes `sessions` rows by userId after rehash (D-07.1, Pitfall 1) |
| T-09-06 | Information Disclosure | reset token exposure | mitigate | Action returns `{success}` only; token lives solely in DB + emailed link (D-06) |
| T-09-07 | Denial of Service | reset-trigger flooding | accept | Admin-gated surface (small); delete-prior bounds live links to one. Per-account rate-limit deferred as low-value on a single-owner store (OWASP) |
</threat_model>
